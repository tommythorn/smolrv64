# Plan: IPC, in measured order (2026-09-05)

Every item below is justified by a number measured on this core this week, names the
mechanism, the effort, and the gate. Each non-trivial RTL change is validated on the board
to `login:` with zero faults (`tools/board-gate.sh`) before the next lands on top of it, and
work continues while a bitstream builds and boots. Status is kept in this file.

## The measurements this plan rests on

full event set** (the first run had stopped at r0312 and reported 46% "unattributed"):

## The items, ranked by payoff per effort

### 1. Name the bubble -- DONE 2026-09-05
The perf run above. `tools/perf-cpi-stack.py`'s usage line now lists r0313-r0316, so the
straddle and queue buckets are always collected. Nothing else to build.

### 2. Fetch: a 16-byte window that keeps the F/X queue fed
**Why:** 41.7% of sha256's cycles are the two fetch buckets above. The window is `HW=4` =
8 bytes, two 32-bit instructions; the fetch buffer keeps ONE I$ request in flight; a 32-bit
instruction across the window boundary is refetched (the aligner "excludes a straddling
32-bit op from the window", `src/fetch.v`), and every cycle the aligner produces nothing,
the F/X queue runs empty and the next instruction pays the queue's registration cycle.
**What:** `OOO2_HW=8`: 16 bytes per window, four 32-bit instructions, straddles halved, and
the queue stays non-empty at one dispatch per cycle. It is gated only by
`smolrv64_sdpram`'s geometry guard on the I$ read width (`RDW=128`). Then a second I$
request in flight from the fetch buffer (the I$ accepts one read per two cycles, so two in
flight is the same 8 bytes/cycle the window gives). A leftover-halfword buffer in the
aligner (merge the straddling half with the next window instead of refetching) is the
third step if the straddle bucket is still visible after the window.
**Measure:** a bare-metal straight-line 32-bit ALU loop (`workloads/febench`) under the
testbench, before and after; then sha256sum's stack on the board.
**Effort:** days. **Timing risk:** the aligner's mux widens; the I$ has 40 MHz OOC margin.
**Gate:** febench, the cosim, the board.

### 3. Senior store queue (the irrevocability pointer) -- DONE 2026-09-04 (board pending)
**Why:** a store's ROB slot completes when the cache takes the write, so the head sits on
every store for ~6 cycles and the 16-entry ROB starves dispatch on store-dense code.
**What:** a second ROB pointer walks forward from the head over entries that are done and
cannot restart (not faulted, not a mispredicted branch awaiting its drain, not a system,
fence.i or interrupt pseudo-op; in-flight loads do not block it, their fault is decided
before the access). Stores at or behind it are committed: their ROB slot completes, the
head moves on, the store queue drains behind retirement. The store queue's flush becomes
partial (keep committed entries, drop from the first uncommitted); "uncommitted" for the
load alias check keeps its meaning (still in the queue). Side effect: more loads find no
older store live and take the early start, a cycle each.
**Effort:** a day or two. **Gate:** tb_ooo2_lqsq (+ a case for the partial flush), the
random bench, cosim, the board.

### 4. The cache's write path -- DONE 2026-09-05 (4a+4b on the board as N, 4c pending)
**Why:** the store queue is full for >= 16 M of 60 M boot cycles because the D$ takes one
write per ~6 cycles, and only while no fill is in flight (a write is SOLO). Item 3 removes
the coupling to the head; this removes the six cycles.
**What:** ack a store on ACCEPT, take a write under a fill, pipeline the write behind the
next lookup (a write is solo because it shares the fill machine's window registers). The
hazard, a load to a line whose write is still in the pipeline, is a one-entry compare.
**Measure:** stbench 5.88 -> ~2 cycles per store; the boot's `sq_full`.
**Effort:** days, in the timing-critical module (rules I6-I9; the census on the shipping
directive judges it). **Gate:** run-ooo2-cache-tb both shapes, stbench, cosim, the board.

### 5. The mispredict drain
**Why:** a resolved branch waits for the ROB head before it redirects (`head_block`), up
to 16 retirements plus the refetch. sha256 has 7.8 redirects per thousand instructions;
the branchy Geekbench workloads (Navigation, HTML5, SQLite) have several times that.
**First:** one counter, cycles from resolution to redirect, on the stack. Then P7 (the
rename walk-back) if it is large.
**Effort:** the counter an hour; P7 days. **Gate:** cosim, the board.

### 6. D$ next-line prefetch, as an experiment -- DONE 2026-09-05 (board pending)
**Why:** the D$ fill machine is busy 33% of boot cycles at one line per ~35 cycles, and
page copies and memsets are sequential. The I$ already has the stream buffer (`PF_EN`).
**What:** `PREFETCH(1)` on the D$ instance plus one rule: any CBO or invalidate drops the
buffer (DMA memory is reconciled by CBO only; a stale prefetched line must not survive it).
**Measure:** boot retires at 60 M cycles; a memcpy microbench.
**Effort:** an afternoon. **Gate:** cache tb (add a prefetch-vs-CBO case), cosim, the board.

### 7. virtio-net burst DMA -- word DMA DONE 2026-09-05 (board pending); bursts later
**Why:** NFS boots and every file over the network are bound by the device, and its queues
are already 256 deep. `src/virtio_net.v` fetches each 64-bit word of a frame with its own
DMA round trip (`S_FRAME_RD -> S_WAIT_FRAME`) and copies it into the engine one byte per
clock (`S_FILL`); a 1500-byte frame is ~190 round trips plus 1500 byte-cycles, on the order
of ten thousand cycles per packet each way.
**What:** read and write frames as 64-byte lines (the line port, one request per 8 words)
or as pipelined word requests with several outstanding; move bytes into and out of the
engine 64 bits at a time. Both queues, TX and RX.
**Measure:** `iperf3` / a large `dd` over NFS on the board, before and after.
**Effort:** days. **Gate:** src/run-virtio.sh (net variant), the board with NFS root.
**Note:** virtio-blk's queue is 8 (two requests in flight). Raising it to 128 in the board
top and the bench panicked at the root mount on 2026-09-05 (`VFS: Unable to mount root fs
on unknown-block(254,1)`); a queue-8 control run is in flight. Not committed until the
device works at the deeper queue; the indices are 16-bit throughout, so the cause is
elsewhere (feature negotiation or the SD backend's chain walker are the suspects).

### 8. An L2 in URAM
**Why:** the KU5P has 2.3 MB of URAM unused; DDR reads cost 29 cycles; the board's operating
point is miss-bound (D$ fill busy a third of boot cycles). A 1 MB L2 at a handful of cycles
is a several-fold cut in miss cost for every working set that fits.
**What:** a direct-mapped or 2-way URAM cache on the 64-byte line port, physically
addressed, write-back, with the DDR behind it; the testbench's DDR model gains the same
stage so the cosim measures it.
**Effort:** a week. **Gate:** cache tb for the new module, cosim at the measured model, the
board.

### 9. Load-use: VHPR plus squash-and-replay
**Why:** the bank address is the PA, which is late (the dTLB compare at the end of M), so
the cache accepts in M+1; a virtual index and tag make it the early VA and the accept cycle
disappears: 5.00 -> 4.00 cycles per load; a raw BRAM word delivered in the compare cycle
would make it 3, if BRAM -> way select -> PRF write fits 6 ns (OOC to prove). ~3% of boot
cycles; more on pointer chasing.
**What:** the read starts on the VA in M; the alias verdict (`e_block` for the entry the tag
names, known at the end of M) and the translation fault cancel the response by tag and the
entry becomes a queued candidate (the existing path); a TLB miss drops and requeues.
VHPR's synonym, ASID, epoch and CBO machinery per docs/VHPR.md; CBO on the I$ through the
physical tags. **Before it:** DMA and synonym coverage in simulation (the D$ bench's T8-T13
and a system-level DMA agent), because both bugs of 2026-09-04 lived exactly there and the
cosim is blind to it.
**Effort:** weeks. **Gate:** the coherence benches, cosim, the board.

### 10. Two-wide dispatch
**Why:** "issue / retire" is 43.6% of sha256's cycles: the one-per-cycle floor. It pays
nothing until fetch delivers two per cycle (item 2) and the stalls above are gone.
**Effort:** weeks (rename, IQ and ROB write ports). Last.

## Not IPC, but decides whether any of it ships

### F1. A flight recorder for wedges
A retire watchdog that, after N cycles without a retirement, freezes a register block (PC,
ROB head state, LSU FSM state, `o_v`, queue occupancies, the last DDR request) readable
over the JTAG debug hub with no ILA build per probe set. The J wedge (2026-09-05,
Geekbench's Structure from Motion, no console output, no ping) could not be asked anything.
Until it exists: J rebuilt with `ILA_CORE=1` plus a probe set on the fast path.

### F2. A coherent I$ with fence.i as a drain
Write-update on resident lines, CBO honoured by both caches through the physical tags, the
I$ miss cleaning its line in the D$ before filling, fence.i as pipeline drain plus queue
drain. Removes two full cache walks per fence.i: 4-15 k per boot, none in benchmarks. Boots
and shells only; after item 9, whose physical-tag path it uses.
