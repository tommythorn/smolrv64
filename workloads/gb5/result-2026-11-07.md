# SmolRV64 -- Geekbench 5.4.1 (RISC-V preview), 2026-11-07, the store queue's page bits

Board build of 2d5ae1d8 (github main 5800b17c's RTL): the store queue's alias test narrows an offset
overlap by the low bits of the two physical page numbers (from M's lookup or the walker's answer, a cycle
after the address arrives), so a load no longer waits for, or replays behind, an older store to the same
page offset in another page; with the fix that holds the ROB's irrevocable pointer in the cycle that
page-qualified flag rises. WNS +0.0016 ns (`Explore`; `AltSpreadLogic_medium` missed -0.166), gate PASS
on the 2 GiB board (login, 900 s of Geekbench, zero faults, integrity log clean); a fresh boot, Ubuntu
over NFS, Geekbench run alone under `perf stat` (the `td` set, every counter at 100%) with nothing else
on the board (one ssh to start it, the results read over NFS); no faults.

Six scores cross a point's edge: Navigation (44 -> 45), HTML5 (20 -> 21), Text Rendering (21 -> 22) and
N-Body Physics (22 -> 23) up, Face Detection (23 -> 22) and Camera (9 -> 8) down. N-Body (+6.2%) is the

Rendering are back where a814eba8 had them. Camera is the one loss, and it is the board's spread rather
than the RTL's: its SimPoints run main's cycles to 0.01%, and one bitstream (l1eco) has run it in 64.8 s
on this board and 68.7 and 69.4 s on the 4 GiB one -- the same 7% this run moves it.
